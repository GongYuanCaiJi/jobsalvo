# jobsalvo 功能清單

選擇與改動相符的驗收頁，逐項執行該頁列出的使用者入口。功能的使用者可以是人，也可以是程式：看板畫面是人用的入口，[真實平台的程式流程](#真實平台的程式流程)是程式自己的入口。

每頁最後的 `Coverage` 列出它涵蓋的原始檔、最後確認同步的 commit 和記錄的破壞（每個破壞該在哪個檢查失敗）。確認功能頁描述的是新 commit 的程式後，才把 `Sync commit` 往前移。程式改了之後，用 `/maintain-verification-skill` 對照原始碼與實際畫面核對功能頁、重播破壞。

## 驗收基準

- **Proof:** `VERIFIED` 要求操作前後的畫面、持久化狀態與可觀察副作用一致；其餘都是 `NOT VERIFIED`，寫明未通過的條件，包括副本缺少前置資料或證據保存不了（原因寫進該功能頁 Gotchas）。本機 `job_fake.py` 路由只產生入口可達與畫面反應的結論；其建立的卡片只納入本機入口觀察。真 agent 與真平台結果依真實流程頁的證據判定。
- **Feature contract:** 每列對應一個使用者功能及其完整入口。以 `board/` 畫面和 `board_server.py` 路由更新入口清單；把未列出的現有入口記為缺口。工具參數以 `--help` 和設定檔為準。
