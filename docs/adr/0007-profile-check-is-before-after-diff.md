# 平台履歷同步：agent 從程式讀到的段落挑位置

每一處原稿各做一輪。agent 先打開可直接輸入的編輯頁；程式讀 R0，留下網址、文件識別、閱讀段落與截圖，並把有編號的 R0 段落交給 agent。agent 一定挑這一處的原文編號（與原稿相同也要挑），再挑會跟著修改一起變的段落（例如字數計數）；沒有原文才回空陣列。範圍由 agent 決定，在同一頁輸入而不存檔；原文已相同就不改。這一處的原文由程式的 R0 段落決定，無須 agent 另抄字。

程式只讀一次 R1。網址變了表示 R0 讀在錯的頁（agent 輸入時才換到真正的表單）：重新載入撤掉沒存的輸入，請 agent 直接打開那一頁，重讀 R0、重做這一處一次；R0 到 R1 期間頁面重新載入（文件識別變了）也一樣重做一次。第二次還換頁或重新載入，就記為 agent 沒停在待輸入頁，停止這一處。範圍外多出來的段落（例如頁上的「8分鐘」跳成「10分鐘」）跟範圍外消失的段落一樣，不算這一處的改動；同一位置只有數字在跳的段落（時間、字數計數）也不算消失。範圍外的變動照次數扣：同一段文字在範圍內外各一份（例如單一大欄位的編輯框和預覽），只扣範圍外那一份。agent 選進範圍、改後不見的段落，必須是這一處的舊稿或新稿，或內容仍留在改後頁面（在同一段裡就地修改）；都不是就是這一處刪了別段（2026-10-14 LinkedIn「關於」整欄被換成單一段），撤回並停止這一處。選進範圍的網址也掛在媒體上（嵌入的影片）時，改後那個媒體不見、又沒有在這一處換上新的媒體（範圍外新放的媒體不算；網址解開編碼再比），是刪掉不是換成新值，同樣撤回並停止這一處。agent 挑了原文、改後原文一段都沒動、只在旁邊多了段落，而原文不是新稿的一部分（不是在後面補一段），是舊稿還留在平台上，同樣撤回並停止這一處。否則比較 R0/R1：整段移位但仍存在，不算消失。這一處範圍外消失的段落不擋：網頁會跟著操作或時間自己變（例如浮動按鈕收起），只看文字分不出是不是履歷資料；這些段落連同改前改後截圖列在「確認送出」畫面給使用者看。這一處改後的內容是新增的段落加上範圍裡沒動的段落，照頁面順序（只改其中幾行時，沒動的幾行也屬於這一處）；與原稿或使用者確認的寫法相同記「照原文」，不同記平台專用、待確認的 agent 代填。R0/R1 沒變時，用挑出的 R0 段落與原稿判斷。平台上原有但原稿沒寫的內容，只要沒有改動就保留。

只驗收時，重新載入並在「離開網站？」選離開，agent 回到同一處，程式讀 R2 一次：挑出的 R0 段落都在，新增的段落都不在。只驗收要防的是放入的內容留在平台上：R2 裡新增的段落都在，記為平台自動存檔、已套用；只留下一部分才算失敗；都沒留下但這一處和改前不同（例如網站自己的草稿被清掉），附截圖列給使用者看。正式同步時，有內容修改就由 agent 存檔、重新載入並回到同一處，程式讀 R2 一次：新增段落都在。擋下的只有這一處沒做對（撤回後原文沒回來、存檔後新內容不在）與讀取失敗。改前改後截圖留給下一張使用這份平台履歷的卡，在「確認送出」畫面驗收，同一處只列最後一輪（平台上現在的狀態）；待確認的代填照常用答案檢查清單擋住確認送出。

## 原因

舊流程讓 agent 抄頁面文字，再由程式讀另一個時間點的頁面核對。兩次讀取之間可能換頁、重新載入或收起編輯框；重抄和等待文字出現都無法保證是同一狀態。R0 段落由程式自己讀取並交給 agent 挑位置，R1 的網址與文件識別負責約束改前改後仍是同一頁。2026-10-13 的 1111 證據顯示，agent 只讀欄位、沒有修改時，頁尾問卷連結仍在 R1 消失、重新載入又出現；因此同一頁也不能推定只有 agent 造成變動。

## 取捨

- 有些網站每一區各有儲存鈕，就每區各跑一輪 R0/R1/R2。
- 原文放不進去時，agent 用平台可接受的寫法；程式記為待確認的常用答案，不另設核准關卡。
- 一份失敗只停同一平台後面的份數，其他平台照跑。
