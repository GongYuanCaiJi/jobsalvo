# 網站任務:程式是 agent 自己叫的拍照比對工具,不停下、不定平台格式規則

ADR-0010 讓程式排好「agent 開頁、程式讀、agent 改、程式讀」的流程,讀不到、太長、核對不過時由程式明確停下;第一次上真平台,這些停下全被報成失敗,接著就有人為了讓它過去放寬一字不差(電話去橫線)。改成:程式只是 agent 自己叫的工具,頁開好叫拍改前、改完存好叫拍改後,程式讀 agent 開著的每一頁、比較、把每一處改動和 agent 說法對不上的地方全部列給使用者;停不停、頁載完沒、平台上的字跟原稿意思上算不算一樣,都是 agent 的判斷,程式和給 agent 的指示裡不寫任何平台格式規則(例如去橫線再比)。程式只做不看網站的核對:agent 引的字在不在頁上一字不差出現(ADR-0009)。這是本產品的取捨:每條平台格式規則只對寫它時看過的網站成立,範圍外不保證,只會越補越多(docs/research/2026-10-25-how-to-make-agents-generalize.md 第 7 節)。

## Consequences

- ADR-0010 的其餘部分照舊:讀 agent 開著的每一頁、每一處改動附改前改後截圖、程式不分哪段是要改的哪段是誤刪的、恢復由使用者按、程式讀不到的邊界。
- agent 先改了才叫拍改前,改前就已經少了東西:改動清單最上面列出拍改前之前 agent 做過的步驟和截圖,並標明這段期間的改動程式沒比對到;只列不擋。
- agent 停下時引不到段落(頁上沒字、讀不到),就附網址和截圖,清單標明這是 agent 的說法、程式核對不了。
- 平台自己改格式(電話加橫線、附件名少副檔名)時,那一處有改動、而原稿沒在頁上一字不差出現時,標「原稿沒在頁上一字不差找到」,由使用者看截圖。
