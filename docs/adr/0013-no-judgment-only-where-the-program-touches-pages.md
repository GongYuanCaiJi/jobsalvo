# 「程式不判斷」只限碰網頁那一段;用使用者設定判得出來的歸程式

ADR-0012 的總規則寫「程式碰網頁只做三件事……此外程式不判斷、不擋」。#601 重寫找缺時把後半句讀成整條流程都不判斷,把重寫前由程式依使用者設定判的事改成把設定原文交給 agent 判(`tools/find.py` 的 `user_materials` 寫「全部原文交出,程式不拿它們篩候選」)。使用者 2026-11-23 釐清,原話:

> 我原先講的是『程式不判斷』，但其實只有一段程式不判斷。
>
> 其他段其實能讓程式判斷的，本來就該讓程式判斷，能讓 agent 不用做就不用做。
>
> 純 agent 處理的部分其實就只有一段而已，但之前 agent 不小心擴張了。
>
> 我們舊的做法才是對的，舊的那一塊程式的做法才是對的。

## 決策

- **「不判斷」只限碰網頁那一段。** 程式讀頁只做拍照、比對前後、核對 agent 引的字一字不差出現在頁上(ADR-0012 照舊)。頁上寫的是什麼意思由 agent 看懂,交出引句核對得到的值。
- **核對過的值加上使用者自己的資料判得出來的,歸程式判,不交給 agent。** ADR-0012 第 4 點的「使用者資料:設定、登記檔、看板狀態」就是這一類;總規則的「此外程式不判斷、不擋」只講頁面內容。這一條適用每一件任務。
- **agent 只做三件事:** 看懂文字(頁上的字、使用者寫的喜好原話)、寫東西、在網站上操作。程式已經算得出來的,不再叫 agent 判一次,也不叫它交一欄沒人用的值。
- **找缺照重寫前的程式接回**(`caf1f420^` 的 `research.py`、`converge.py`、`find_terms.py`):板上已有、以前判過 agent 說不投的網址,讀頁前清掉;核對過的職稱中「一定不要」、核對過的公司是封鎖的那家、核對過的值不符這輪條件,不成卡;agent 判成詐騙而且核對完整的,不成卡。
- 找缺與貼網址:幽靈職缺不再叫 agent 看「刊登很久、重貼」,刊登天數看板拿核對過的刊登日比使用者設的天數,同公司同職稱的舊卡由程式比(J-17,重寫前的 `research.add_repost_hints`);agent 只看 JD 空泛、只寫人才庫這種要讀字的跡象。貼網址不問 agent 送不送。
- 算術歸程式:薪資由 agent 照頁上原文交金額、幣別、月薪或年薪,換成新台幣月薪由程式做(年薪除以 12、外幣照當天匯率)。匯率來源見下面「匯率」。
- 程式或 agent 丟掉的每一張都讓使用者看得到(J-24):看板逐張列出哪一條規則或 agent 的原話、程式讀到的那一頁截圖、核對過的值,丟錯的一鍵加回看板。agent 判過不送的網址之後不再讀(J-13),所以看板另有一塊一直列著全部,不只最近幾輪。程式判得再準,使用者還是要能自己檢查。
- 沒核對到的值不拿來判(行為 J-07);照使用者設定擋的每輪重算,不記進判過不送(J-13);使用者自己貼的網址一律成卡(J-16)。

## 後果

- 給 agent 的材料不再放程式會判的設定(排除字、排除職稱正規式)。封鎖名單照交:別的寫法、簡稱由 agent 判,一字不差的由程式擋(J-12)。「要小心」的字照設定頁的說法交給判斷那一段看。
- 看板上的「不符條件」「查不到」是程式算的,不再標成 agent 回報。
- 匯率用 ExchangeRate-API 的免金鑰版(`open.er-api.com`,每天更新、准快取、要標出處):臺灣銀行牌告匯率 CSV 會回驗證頁、程式抓不到;歐洲央行的參考匯率(Frankfurter)沒有新台幣;中央銀行網站的憑證驗不過。程式每天抓一次存在使用者資料夾,抓不到用上次的,都沒有就外幣薪資算查不到。看板找缺條件「月薪」旁標出處。
- 根因修在原處,不在現有程式上疊一層。使用者原話:「這個程式是我們自己的 repo，不要一直打補丁，就是不准打補丁。能處理根因就處理根因，不准在程式上面多疊任何一層補丁。」
