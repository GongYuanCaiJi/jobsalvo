# agent 指段落編號,要當值的再寫出原文;程式用同一種方式讀每個網站

把 ADR-0007 的編號做法推到每一個 agent 要拿材料當證據的地方(#465)。程式只做不用看懂網站的事:用同一種方式讀頁面、切段、編號、印上交付代號,核對 agent 回的號碼是這一份裡的。要看懂頁面才知道的事(哪一段是職稱、公司、刊登日、職缺關了沒、哪句是拒絕信)交給 agent 判斷。只當證據的,agent 回段落編號,卡上顯示那幾段原文;要當成值用的(卡名的職稱與公司、改卡名、信件標題),agent 另外寫出值,程式只在它指的那幾段裡確認這個值一字不差地出現,有就收、沒有就不收。這是研究第 2 點「AI 附上原文、程式核對原文真的在程式讀到的頁面裡」(研究見 docs/research/2026-10-08-agent-verification.md;它引的 Google LangExtract 也是每個抽出的值對到原文位置),編號只是把核對範圍縮到 agent 指的那幾段。不認平台名稱,也不為任何平台補專用讀法:真實世界的網站有無數種寫法,一平台一套永遠補不完,平台一改就壞。

## Considered Options

- **agent 抄原文、程式到整頁裡找**:程式收集頁面文字時漏一塊,真的在頁面上的話也找不到;每對不上一次就補一條寬鬆規則(空白不算、全半形當一樣),補到 13 處各自一套(#465)。
- **程式從平台欄位或介面讀(104、Lever、Ashby、Greenhouse 的欄位,或 schema.org JobPosting)**:只對有那個欄位的平台成立,其他平台照樣要問 agent,等於兩條路;#465 真實驗收時卡名改看平台欄位,已撤回(#468)。
- **要當值的也直接用整段原文**:一段常同時有標籤和值,卡上的公司變成「公司: 昌捷…」,跟其他卡的「昌捷…」比不起來,同一家分成兩組。
- **刪掉標籤字**:要先知道每個網站用哪些標籤字,就是平台補丁。
- **證據回段落編號;要當值的另寫原文,只在指的段落裡一字不差核對(採用)**:只有「有」或「沒有」,沒有寬鬆規則;agent 只看得到程式印給它的段落,不會有「頁面上有、程式手上沒有」;agent 最多指錯位置,沒辦法捏造內容。

## Consequences

- 抓職缺頁目前仍有一平台一套的讀法(#60 時選的平台介面、只對某些平台成立的日期與應徵人數讀法),跟這條衝突,在 #471 收掉。
