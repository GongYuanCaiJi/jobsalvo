# 每個 PR 一個預覽看板,用真實資料的副本

維護者每天用看板求職,同時有好幾個 PR 在開發。原本想用一個隱藏的總開關(#801)把半成品包在 main 裡,只給維護者看。維護者否決了:打開後所有半成品一起出現,不能只看某一個 PR,也看不出它跟 main 差在哪。

## 決定

- 業界看開發中的東西是每個 PR 一個預覽(Fly.io、Render 的 per-PR preview;SSW 在桌面 App 設定裡切到某個 PR 的預覽版)。jobsalvo 照這個做:正式看板上列出開著的 PR,挑一個就另起一個看板,跑那個 PR 推上去的最新 commit。
- 預覽用真實資料的副本,不是假資料;寫入只到副本。資料隔離沿用現有的副本規則(看板檔不是正式那一份,伺服器就當副本:設定與履歷複製一份、連外與送出不做真的事、改不了開機服務與更新)。不讓預覽冒充正式看板。
- 預覽跑的是 PR 分支自己的看板伺服器,舊分支沒有這次的程式;所以抓程式、複製看板、挑埠號、記錄、清理全在正式看板這邊做,預覽那邊只用早就有的「指定看板檔」與「指定埠號」。
- PR 都開在私人的開發 repo(ADR-0002),程式直接寫明去那裡找;這台電腦登入的 GitHub 帳號能推送它才有這個功能,不用任何設定,其他人看不到。代價是公開 repo 的程式裡會出現開發 repo 的名字(看不到內容)。fork 來的 PR 一律不列:不在真實資料的副本上跑陌生人的程式。
- PR 合併或關掉後,它的預覽與程式資料夾在下一次列清單時清掉。

## 後果

- 想看哪個 PR 不必切分支,也不必先合進 main;正式看板照 ADR-0013 只跟 main。
- 預覽裡填表、同步、找缺照副本規則不做真的事;可投遞夾的建置產物不複製,相關畫面可能是空的。
- 預覽分頁上方的「這是哪個 PR」只有包含這次改動的分支會顯示。
