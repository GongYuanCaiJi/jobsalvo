# 看板只送指令,後台套用並回復原單

以前看板有兩條寫入路:按鈕送事件,其他改動(心情、筆記、常用答案、封鎖名單…)整張卡送回去。整張送就會蓋掉別處剛改的,只好再疊三層補丁:版本比對(撞到回 409)、撞到之後的逐格合併(`merge_edit`、`/api/merge`)、事件被擋時保留流程欄位(`keep_flow`);復原則是每顆按鈕各寫一段反操作(28 處),投遞後的結果日期看板和後台各算一份,確認送出後 8 秒的計時器放在瀏覽器分頁裡(分頁關掉就不送了)。

改成看板只送**指令**(哪一份、哪個事件、改哪幾欄),後台套在現在那一份上,回每一道的**復原單**(動到的欄按之前、按之後的值);復原就是把復原單送回去,別處改過的欄不放回,狀態表管的那幾欄一起放回或一起不動。記結果是狀態表上的一個事件;確認送出之後排在後台 8 秒才送,這段時間復原、取消確認,時間到就不送。

## Considered Options

- **保留整張送,把合併做得更完整**:每多一種資料(清單、巢狀欄位)就要再教合併一次,每顆新按鈕還要再寫一段反操作。
- **只送指令、後台回復原單(採用)**:沒有整張送就沒有蓋掉,也就不用比版本、不用合併;所有按鈕的復原都是同一件事。

## Consequences

- 同一欄兩個分頁都改了,後到的贏;看板從復原單看得出那一欄按之前不是它以為的值,就告訴他,按「復原」換回那邊的。
- 舊版分頁(還在送整張卡)存檔會被擋,請他重新整理。
- 伺服器重開時排著的送出會掉:卡停在你已確認,卡上給「▶ 送出」。
