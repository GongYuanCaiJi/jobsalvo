# 一張卡的所有判斷只在後台算一份,看板照著畫

取代 ADR-0004 的第三條後果(看板和後台各有一份讀狀態的判斷)。狀態表讓兩邊「狀態怎麼走」一致,卻沒讓「判斷」一致:停著的頁、能不能確認送出、會不會自動重打、投遞前把關、常用答案等不等你、哪幾種狀態算忙、卡名和公司名,兩邊各手寫一份,寫好之後又分歧了五處(使用者推翻 agent 判斷後兩邊不同步、只缺證據的答案看板說會自動重打、只要重翻的卡看板沒講、送出中換檔沒標舊檔、公司名大小寫),後台收到確認送出時也不跑檢查清單,只靠畫面的灰按鈕擋。改成後台是唯一算判斷的地方,算出每張卡的下一步送給看板;看板只送事件、照回來的結果畫,不再自己套狀態表。狀態的分類(停著、忙、能換檔、能離開、算填好)寫在狀態表上,不再在各處列狀態名。

## Considered Options

- **兩份照舊,補更多比對案例**:案例由舊資料轉換產生,新欄位永遠列不到;每加一條規則就多一處要對齊,漏一處就是畫面講的跟程式做的不一樣。
- **後台算一份,看板照畫(採用)**:「要寄的檔案」已經這樣搬過(#304),按了就問後台,沒有出問題。

## Consequences

- 看板按下去要等後台回話才更新(本機幾十毫秒);改答案要等自動存檔,約一秒。等的時候卡片維持原樣、按鈕先停用。
- 兩邊逐格比對的檢查、兩邊各跑一次的案例表、掛在正式頁面上的測試入口都刪掉;判斷改在後台直接測,看板檢查只測「照後台給的畫出來」。
- 後台收到確認送出時照檢查清單擋,不再只靠畫面。
