# 網站任務程式的結構:頁面內容只准白名單函式讀,瀏覽器是唯一外部邊界

ADR-0011 定下程式是 agent 自己叫的拍照比對工具:「程式不停下、不定平台格式規則」,只做一字不差的核對(ADR-0009)。#601 收尾時四件網站任務照票修了好幾輪,每一輪都有地方又長出依頁面下判斷的程式:`docs/research/601-behaviors.md` 的 R 段把 268 個修正歸類,光是「先改寫字再比」(R-05)和「依頁面猜事情」(R-06)就有 52 個。規則寫在文件裡擋不住,這份 ADR 改用結構擋。

## 決策

**總規則**(使用者 2026-11-12 定,decisions.md 原文照抄,全文在附錄):程式碰網頁只做三件事:拍照、比對前後、核對 agent 引的字一字不差出現在頁上。此外程式不判斷、不擋;看到什麼照實列出,標明是程式讀到的、agent 說的、還是程式沒比到。任何依頁面內容下判斷或擋東西的地方,一律刪掉,不另留提醒句。

**交件單的判斷欄**(這次重寫的指示寫明,延伸自 ADR-0011「判斷歸 agent」):agent 交件單上的判斷欄是 agent 的結論,程式照實記錄、照它分流;agent 引的頁面文字和拍到的頁面是頁面內容。

1. **頁面內容是不透明型別。** 拍到的每一頁(分頁、網址、段落、讀取狀態、截圖)只存在 `web.seen.Seen` 裡;agent 照抄的頁上文字(交件單的引段值、`needs_user_quote`、`changes` 的改前改後、`unmet.quote`、`risk_quote`、回音的主旨與引句)只存在 `web.seen.Quote` 裡。兩者欄位名一律 `_seen_` 開頭,全 repo 只有這兩個型別用這個字首;不是 dataclass(`__slots__`),相等、雜湊、字串化、格式化、逐項取出、包含、序列化一律丟錯。判斷欄(agent 自己的結論:列舉、數字、它的話)照原值給任務檔。任務程式拿到它只能交給下表的函式。瀏覽器回的原始資料轉成段落也在 `web/seen.py`,在驗收與突變測試的範圍內。核對與比對回傳程式自己的分類(句子代碼與讀到沒有),不回傳頁上的字;要顯示的原文由「列出」那一組函式直接寫成看板格式。
2. **瀏覽器是唯一外部邊界。** `web.outside.Browser` 一個介面收齊:列分頁(含網址)、讀一頁、截一頁、讀一個網址、讀與填申請表的格子、開一個空工作區、把一頁交到使用者面前、跑 agent。正式版 `outside.Real` 接 ego、直接抓與閱讀代理、`agent_run`;測試接假的。agent 算邊界外的輸入:它只經由拍照工具與瀏覽器動作影響程式,程式不看它怎麼操作。
3. **共用核心四件事,每件任務一個檔。** 拍照(`web/snap.py`)、比對(`web/compare.py`)、核對(`web/cite.py`)、列出(`web/listing.py`),加上型別與讀頁(`web/seen.py`)、邊界(`web/outside.py`)。四件任務各一個檔(`sync.py`、`fill.py`、`progress.py`、`find.py`),只寫自己的主線:組材料、跑一輪、照下面的封閉清單分流、把核心給的結果交給存檔。另一個入口 `add_job.py`(貼網址加卡,走找缺那一套)和 agent 叫的工具(`jobsalvo-before`/`jobsalvo-after` 是 `snap` 的入口、`page_fetch` 是 `seen.fetch` 的入口、`form_plan` 是填表的工具)算同一層,受同樣的 lint 與測試範圍。
4. **任務檔准照分流的,只有這幾種(封閉清單)。**
   - 交件單判斷欄的值,與引段那一格核對過沒有;沒核對到的值不拿來自動做決定(行為 A-40)。
   - 這一輪怎麼結束,agent 叫了拍改前、拍改後沒有。
   - 核心回的是或否:`cite.fixed_profile`(F-10)、`cite.record_page_present`(P-09、P-11)、`cite.rows_by_url`(交件的列對到哪一頁)、`seen.has_tab`(交接)、`cite.same`(核對過的引文跟使用者資料一字不差相等,C-21)。

   任務檔拿到的比對、核對結果是不透明的列(只能交給 `listing`)加上這幾個具名的是或否;步驟四要依別的事實分流,就在核心加一個具名的是或否,寫進這張清單,不開 lint 例外。
   - 使用者資料:設定、登記檔、看板狀態。

   其他分類(句子代碼、讀取狀態、配對的種類)只准交給 `listing` 與存檔。
5. **lint 擋旁路。** `.semgrep/page-content.yml`,錯誤訊息寫要改用哪個函式:
   - 核心以外的任何模組取 `_seen_` 欄位。
   - `web/outside.py` 以外的任何模組直接叫讀頁或讀網址(工作區讀頁、讀表單、直接抓、閱讀代理)。
   - `web/outside.py` 的讀頁方法一律 `raw_` 開頭(`raw_tabs`、`raw_shot`、`raw_fetch`、`raw_form`,規則照名字列),核心以外叫就失敗。
   - 任務檔與同層的入口:用 `getattr` 拆物件、讀看板格式裡裝頁上原文的鍵。
6. **驗收與突變測試的範圍。** branch coverage 與 mutmut 只算邊界以內:第 3 點列的任務檔、入口與工具,加上 `web/` 核心,不含 `outside.Real`。驗收測試的接縫照這次重寫的指示,只有任務入口加上假瀏覽器邊界,同一個行程裡跑完。真瀏覽器那一側由兩樣驗:開瀏覽器的讀頁測試(留著,改接 `outside.Real`),和第五步用真 agent 在假網站把四件任務各跑一次。

## 能讀頁面內容的函式

C 編號是 `docs/research/601-behaviors.md` C 段的條款;出處寫在那裡。網址只在 C-06、C-15、C-16、C-17 比相等,一律一字不差;C-12、C-13 只取主機名,主機名大小寫不分是網址規格本身。

| 函式 | 做什麼 | C |
|---|---|---|
| `seen.read_workspace` | 讀工作區每一頁,讀不到、沒字、太長、截圖沒取得照實記 | C-01 |
| `seen.fetch` | 讀 agent 交回的網址,三條路依序退;只讀公開 http(s) 網址 | C-02、C-03 |
| `seen.number` | 切段編號、印交付代號 | C-04 |
| `seen.has_tab` | 那一分頁還在不在讀到的工作區 | C-24 |
| `seen.host`、`seen.platform_of` | 取主機名;主機在使用者登記的網域清單裡 | C-12、C-13 |
| `seen.form` | 讀申請表每一格瀏覽器給的名稱與值 | C-23 |
| `snap.take` | agent 叫拍照時讀、編號、存證據夾 | C-01、C-04、C-05 |
| `compare.pair` | 同分頁且網址一字不差才配對,其他三種照實分類 | C-06 |
| `compare.diff` | 配對的頁逐處比 | C-07 |
| `compare.mark_intended` | 原稿標記與刪除讀不讀得到 | C-08 |
| `compare.check_claim` | agent 說的改動對照程式讀到的 | C-09 |
| `cite.pick` | agent 引的值一字不差落在引的段裡 | C-10 |
| `cite.hand_over` | 交出 agent 指的那一分頁,重讀並標引文一字不差在頁上沒有 | C-11、C-24 |
| `cite.fixed_profile` | 拍到的頁網址等於登記網址 | C-15 |
| `cite.rows_by_url` | 判斷交件的列對照讀到的網址 | C-16 |
| `cite.record_page_present` | 登記的應徵紀錄頁在不在讀到的工作區 | C-17 |
| `cite.answers_on_page` | 答案一字不差在頁上 | C-18 |
| `cite.answer_for` | 申請表的格子名稱跟答案庫題目一字不差相等才給答案 | C-18、C-23 |
| `cite.same` | 核對過的引文跟使用者資料一字不差相等 | C-21 |
| `cite.uploaded_names` | 頁上顯示的上傳檔名對照要寄的檔名 | C-20 |
| `listing` 各函式 | 把讀到的原文照原字寫成看板格式 | C-14 |

C-22(交件單的判斷欄照原字存)用的是 agent 自己的結論,不讀 `Seen`、`Quote`。這張表是上限:步驟四沒有測試要的函式不寫,收尾時從表上刪掉。

## 後果

- 任務檔要依頁面做決定,得先讓核心多開一個函式,或在第 4 點的封閉清單加一種;兩者都要在行為清單有出處,code review 看得到。
- lint 認的是名字(欄位、鍵、方法、模組),不是型別:有人把頁上的字先存進別的名字再傳進任務檔,或看板格式寫進檔案之後任務檔再讀回來,lint 抓不到,靠 code review。
- 確認送出畫面那一次拍照(行為 F-14)是程式自己叫的,不是 agent 叫的:看板叫 `fill.py` 的確認入口,它只拍、比、列,不擋,照 #569 US18;decisions.md Q8「確認送出畫面也不放程式推出來的提醒」講的是由頁面推出來的判斷(下架、連結),改前改後照列是比對前後,不在其內。
- ADR-0011 不變。
