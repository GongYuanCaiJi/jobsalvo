# 找缺

每一輪都先做這裡的兩步；這一輪使用者想要什麼，在本輪方式的 skill 裡。

你可能會在程式提供的材料裡看到兩種記憶：

- **角度地圖**：使用者表態過的每個角度，各送過幾張、喜歡幾張、不喜歡幾張、還沒看幾張。角度是一個切入點，例如「雲端基礎設施」「使用者研究」。
- **偏好筆記**：每一條是一個假設，使用者喜歡或不喜歡什麼、為什麼。每條附出處（卡片代號＋使用者的原話），以及目前幾張支持、幾張反例。

這些定義不代表本輪已提供這些材料。只使用程式在本輪材料段落明確列出的內容；沒有列出的地圖、筆記或檔案不要假設存在、不要自行尋找，也不要杜撰內容。偏好筆記分成「使用者自訂」和「Agent 假設」；自訂內容由程式保護，整理時只能更新假設區。

## 1. 整理

只有本輪同時提供「新表態」和可更新的偏好筆記時，才依下列方式整理；少了其中一項就跳過這一步，不建立或修改不存在的材料。新表態只包含上次整理後新增或改變的表態，每張都附原話和完整 JD，或職缺網址與卡片摘要。

- 每條假設都寫出來源卡片、使用者原話、支持數和反例數。新表態支持某條，就把它加進出處；出現反例，就改寫那條或拆成更準的兩條；已經沒有出處撐得住的，就刪掉。
- 使用者的原話是證據，假設是你的讀法。兩者對不上時，照原話改假設。
- 使用者自訂條目與任何新表態衝突時，不改自訂區；把衝突的自訂條目、表態卡片與原話列在交件筆記，請使用者決定是否修改。

整理完成時，新表態裡的每張卡都要出現在某條假設的出處裡，或在筆記最後「還看不出來」那段寫明原因。
把完整新版筆記寫到程式指定的輸出檔，不要改原始檔，也不要改「使用者自訂」區。

## 2. 找

照使用者這一輪想要的，以及程式本輪實際提供的角度地圖、偏好筆記、履歷與硬規則，自己決定往哪些角度找、各找多少。依使用者表態和角度地圖自行決定各角度的份量，不設比例，也不要自創使用者沒說過的禁令或排除條件。同一個切入點沿用地圖上的名字；真的是新的才取新名字，名字寫「在做什麼」。沒有提供的地圖或筆記不算可用依據。

覺得可能對味的職缺就照程式接上的交件格式回覆，每張都要填一個角度名稱。不要自行改欄位或 JSON 格式。這輪用到的每個角度都在交件筆記寫一句為什麼選它，引用角度地圖或偏好筆記的哪一條。
